# Threat model

Adversary: a provider (or set of providers) that wants to be counted as more independent copies than it really holds, while spending less than honest storage would cost. This is the economically rational "cheap-and-lazy" adversary of RAFT (G 9a), Benson (G 6), and Gondree & Peterson (G 7). A fully malicious adversary that controls the Internet path is out of scope: LoSt shows location verification is impossible in that setting (G 8).

> Provenance: statements cited to P, D or G rows trace to the pinned sources in `research/sources-*.md`. Everything else here (engine behaviour, thresholds, sampling, scoring, clustering, the example numbers) is implementation-derived from `engine/` or INFERRED from the linked measurement reports, and is labelled evidence, not proof.

Citations: P = [sources-porep.md](sources-porep.md), D = [sources-pdp.md](sources-pdp.md), G = [sources-ipfs-geo.md](sources-ipfs-geo.md).

## Measurements the engine takes

| name | how | what it bounds |
|---|---|---|
| `advertised` | provider record in IPNI (`/cid/{cid}`, G 2a) or delegated routing (`/routing/v1/providers/{cid}`, G 1a) | nothing: records are self-published |
| `baseline` | median time-to-first-byte of `GET /ipfs/bafkqaaa?format=raw`, which boxo serves "without any blockstore or network lookup" (G 3c) | network RTT to the responder, so d_max = 102.1 km x RTT_ms + 11 km (G 10a: 204.19 km/ms one way in SMF-28 fibre; 11 km for the 0.1 degree rounding of vantage coordinates). G 10b's "100 km per ms" is the rule of thumb, the engine rounds up |
| `probe` | time-to-first-byte of `GET /ipfs/{random block}?format=raw`, interleaved with a baseline request per pair, body hashed against the CID (G 3a) | baseline + storage read + any upstream fetch, as long as the server does not flush headers before it has the block |
| `excess` | median over pairs of (probe minus baseline) | the cost of producing the block beyond answering a request. INFERRED: `local` means "not measurably slower than the no-op", which is evidence of a local read, not a proof |
| `cluster` | DNS A record (DoH), ASN of that IP (RIPEstat), Peer ID | which endpoints share infrastructure. The DoH answer can differ from the IP the browser actually connected to (geo-DNS without client subnet), and one anycast IP can be several sites |
| `disk` | per vantage: circle of radius d_max around the vantage's self-reported location | where the responder can be |

## Attacks

| attack | what the adversary does | check that catches it | stated limit |
|---|---|---|---|
| **Sybil peer IDs** | One box advertises the CID under many Peer IDs or many ContextIDs (IPNI shows one Provider.ID per ContextID, G 2b). Registry lets one entity register many provider addresses for 5 FIL each (D §4) | `cluster`: endpoints are merged by resolved IP into boxes; the separation search runs over boxes, and the ASN-level operator count is the conservative fallback when nothing is proven apart. Peer-ID count is shown but never used in the score | Many IPs in one DC in one ASN look like one cluster (correct). Many IPs across rented ASNs in one DC look like several clusters from one vantage. Only the multi-vantage disk check separates them, and two responders in the same DC always have overlapping disks, so they are never counted as separate |
| **Colocated operators** | Two real operators, two real copies, same building or same cloud region | Multi-vantage: two responders are "proven separate" only if some disk of A and some disk of B are disjoint, i.e. distance(V_i, V_j) > d_A,i + d_B,j. Responders at one point can never satisfy this (both disks contain that point) | This is the intended behaviour: colocated copies share a failure domain and should not raise the resilience score. The cost is false negatives. INFERRED: with browser RTTs of tens of ms, sites tens of km apart will not be separable in practice |
| **On-demand proxying** | Endpoint holds no copy; on request it fetches the block from a real holder and relays it (the relay attack Gondree & Peterson name, G 7). Nothing in the protocol prevents a modified node from doing this (D §7); stock Curio serves only local pieces (D §7) and stock boxo serves only its blockstore (G 5) | `excess`: an upstream fetch adds at least one more RTT. Threshold default 30 ms, which is ~3,000 km of distance at 100 km per ms of RTT (G 10b). Blocks are chosen uniformly without replacement from the sample; INFERRED: a proxy that does not already hold the prefix cannot know which block comes next | A proxy whose upstream is within the threshold (<30 ms RTT, about 3,000 km) passes. A proxy that flushes response headers before fetching the body defeats first-byte timing; the `transfer` field records body time for that case but is not scored. A proxy that delays its own `bafkqaaa` answers lowers its excess and passes (it cannot shrink its disk, only hide on-demand status). The sample is the first 64 blocks of the DAG, so a proxy that caches that prefix passes forever; PDP-style whole-dataset detection math (D §8) does not transfer. The endpoint that served the sample CAR is marked `warmed` because its cache was populated before its challenge |
| **CDN caches** | Endpoint is behind a CDN (gateway-v1.pinata.cloud resolved to a Cloudflare IP in the prototype run). The CDN edge serves bafkqaaa and cached blocks from near the vantage | `excess` is low from a warm edge, so the edge passes as a "copy". `cluster` by ASN flags known CDN ASNs as `cdn` so the UI can label them. A cold edge fetches from origin and fails the excess check | A CDN edge that has the block cached *is* a copy for availability purposes, but not a durable one. Score counts CDN clusters separately and excludes them from the durable-copy count. Detection depends on ASN labelling, which is a heuristic list, not a proof |
| **Dark fiber / private backhaul** | Provider relays challenges between sites over a link faster than public Internet paths, so an on-demand relay looks local (defeats the latency class, not the physical bound on the responder, see limit) | None. Benson et al. and Gondree & Peterson both assume no exclusive inter-DC link (G 6 Assumption 2, G 7 "providers renting dark fiber may undermine such an assumption"); GoAT instead assumes a light-speed adversary and pays for it with prover cooperation (G 9b) | Stated assumption, in two parts. (1) No exclusive link between sites. (2) Paths are fibre or slower: the 102 km/ms radius is light in SMF-28 (G 10a); a microwave or free-space relay runs near c and could appear up to 1.47x closer, which is why GoAT uses c in vacuum (G 9b, 9e). Under (2), dark fibre cannot make a responder appear *closer* than it is, only make a distant copy answer faster than a public path, so the disk stays an upper bound on the *responder's* distance |
| **Lying vantages** | A merged report claims a vantage location it was not at, or fabricates RTTs, to manufacture disjoint disks | Vantage locations are self-reported and the UI says so next to every merged score. Reports carry no signature. Cross-check: the same provider's disks from all vantages must intersect; each provider whose disks from two vantages are disjoint is listed with both vantage names (the same symptom appears when one IP is anycast from several sites). A vantage can shrink its disks (claim lower RTT), which manufactures separation, or enlarge them (claim higher RTT), which hides a real separation; both are undetectable from the report alone | No cryptographic defence. Anyone merging reports from strangers is trusting them. For the MSP placement use case the vantages are the auditor's own browsers, so this is acceptable. GoAT's signed-timestamp anchors (G 9b) are the fix if this ever needs to be trustless, at the cost of needing prover cooperation |
| **Slow-lying** | Provider adds delay to look farther away, or delays only its `bafkqaaa` answers | Adding delay can only enlarge a disk (G 10b, "the adversary may only do so by adding delay"), which never increases the separation count | Delaying only the baseline hides `on-demand` status (see on-demand proxying). The disk stays sound because it is built from the baseline, which only got larger |
| **Selective serving** | Provider holds some blocks, fetches the rest on demand | Random block choice per run within the sampled prefix | Only the first 64 blocks of the DAG are sampled, so this check says nothing about the rest of a large DAG. Within the prefix (derived): with N sampled blocks of which m are missing and k challenged without replacement, detection probability is 1 - C(N-m, k)/C(N, k); for N=64, m=1, k=5 that is about 8%, and only a block that cannot be served at all counts as missing (a slow fetch is a timing class, not a miss) |
| **Stale advertisements** | IPNI still lists a provider that deleted the data | `advertised` vs `served-valid` columns show the gap directly | Not an attack, but the number most people quote ("N providers on cid.contact") is this upper bound |

## What a passing result means

A provider marked `local` served blocks that hash to the requested CIDs, from an endpoint whose extra latency over its own no-op baseline was under the threshold. Two providers marked `separate` answered from responders that cannot both be inside any one point's reach, given the vantages' claimed positions and the speed of light in fiber. Neither statement says anything about durability, about the next hour, or about a provider that is willing to run private fiber to cheat a research tool.
